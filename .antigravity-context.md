# CONTEXTO DEL PROYECTO: SERVIDOR MINECRAFT PAPERMC (TLAUNCHER / GCP)

## 📌 PROYECTO Y ENTORNO
- **Proyecto:** `SERVER_TLAUNCHER` (`Server-Minecraft`)
- **Tipo de Proyecto:** Infraestructura & Despliegue de Servidor de Juegos (Minecraft PaperMC en GCP Compute Engine + Docker Compose + SSH)
- **Motor / Versión:** PaperMC `1.21.1` (imagen base `itzg/minecraft-server:latest`, Java 21)
- **Infraestructura:** Google Cloud Platform (GCP) Compute Engine VM (Debian 12 / Ubuntu 24.04 LTS), orquestado con Docker Compose v2.
- **Modo de Conexión:** Offline-mode / No-Premium (`ONLINE_MODE: "FALSE"`) con soporte cruzado para TLauncher y cuentas Premium de Mojang.

---

## 🚦 LOGROS DE ESTA SESIÓN
- **Blindaje y Seguridad Perimetral:**
  - Puerto de host ofuscado a `28475:25565` en `docker-compose.yml` para bloquear bots y escáneres automáticos de red.
  - Whitelist estricta forzada a nivel de servidor (`ENABLE_WHITELIST: "TRUE"`, `ENFORCE_WHITELIST: "TRUE"`).
  - Autenticación in-game con `simple-login` (`/register` y `/login`) para evitar suplantación de identidad bajo UUIDs no-premium.
- **Curaduría y Optimización de Plugins:**
  - Integración de releases estables por enlace directo en variable `PLUGINS`:
    - `EssentialsX` y `EssentialsXSpawn` (v2.22.0) directos desde GitHub oficial.
    - `TAB` de NEZNAMY (v6.2.0) compatible con Paper 1.20.5 - 1.21.4 (lista TAB, ping en ms, vida en nombres).
    - `Sleep-Most` (v5.5.3) compatible con Paper 1.21 y GSit: configurado para pasar la noche cuando duermen exactamente 2 personas (`players-required: 2`).
  - Plugins automáticos integrados vía Modrinth (`MODRINTH_PROJECTS`):
    - Utilidades/Core: `skinsrestorer`, `luckperms`.
    - Vanilla+ QoL: `instant-villager-restock`, `easyvtc`, `thizzyz-tree-feller`, `harvestmaster`, `gsit`, `invisible-frames`, `fastleafdecay`, `antitrample`, `playerheaddrops`, `damage-indicator`.
  - Diagnóstico técnico de `easyvtc` (ciclado de aldeanos): Identificados bloqueos por cooldown de 5s (`cooldown-seconds: 5`) y cobro involuntario de 3 esmeraldas por tirada (`emerald-cost: 3`).
  - Eliminados `player-chat-heads` (limpieza visual del chat) y `Dynmap` (junto al puerto 8123 para evitar saturación de CPU/RAM).
- **Scripts de Operación y Ajustes de Rendimiento:**
  - Creación de `start.sh` (actualización de imagen, levantamiento en `-d` y seguimiento de logs en tiempo real).
  - Creación de `stop.sh` (apagado ordenado vía `docker compose down` garantizando el guardado del mundo).
  - Flags de Aikar activadas (`USE_AIKAR_FLAGS: "true"`), `SIMULATION_DISTANCE: "4"`, `VIEW_DISTANCE: "10"` y límite de 15 jugadores.

## 🛠️ COMPONENTES Y ARCHIVOS CRÍTICOS
- **Archivos de Configuración:**
  - `docker-compose.yml`: Archivo central con variables de entorno de PaperMC, flags de memoria, puertos y stack de plugins.
  - `start.sh`: Script bash de bootstrap y visualización de logs en vivo.
  - `stop.sh`: Script bash de detención segura.
  - `README.md`: Documentación de despliegue, configuración de firewall en GCP y comandos CLI.
- **Rutas de Persistencia:**
  - `./data:/data`: Volumen local que almacena `world`, `world_nether`, `world_the_end`, `plugins/`, `whitelist.json` y configuraciones.
- **Comandos Recurrentes de Operación (SSH en GCP VM):**
  - Iniciar: `./start.sh` o `sudo docker compose up -d`
  - Parar: `./stop.sh` o `sudo docker compose down`
  - Monitoreo de logs: `sudo docker compose logs -f`
  - Whitelist: `sudo docker compose exec minecraft rcon-cli whitelist add <Nick>`
  - Permisos OP: `sudo docker compose exec minecraft rcon-cli op <Nick>`
  - Consola RCON interactiva: `sudo docker compose exec minecraft rcon-cli`

## ⚠️ ALERTAS Y RESTRICCIONES ACTIVAS
1. **REGLA DE ORO DE RESPUESTA (PROTOCOLO GIT-FIRST):**
   - Siempre que se modifique cualquier archivo local (`docker-compose.yml`, configs, scripts), la respuesta del asistente DEBE iniciar obligatoriamente con los comandos de Git:
     - Local: `git add .`, `git commit -m "..."`, `git push`
     - VM (SSH): `git pull`, `./stop.sh && ./start.sh`
   - Solo después de sincronizar y reiniciar la VM se pueden indicar comandos in-game o de RCON.
2. **Dimensionamiento de Recursos Verificado:**
   - La VM en GCP cuenta con **4 vCPUs y 16 GB de RAM** (`e2-standard-4`).
   - `MEMORY: "12G"` e `INIT_MEMORY: "6G"` en `docker-compose.yml` es óptimo.
3. **Puerto y Regla de Firewall GCP:**
   - El puerto expuesto es `28475` (mapeado al `25565` del contenedor).
   - Los clientes deben conectarse a `<IP_EXTERNA>:28475`.
4. **Comandos de Sleep-Most:**
   - `/sm setflag` solo puede ser ejecutado por un jugador con OP dentro del juego (no por consola RCON).

## 🚀 PRÓXIMOS PASOS
1. **Configurar Ciclado de Aldeanos (`easyvtc`):** Ajustar manualmente con `nano data/plugins/EasyVillagerTradeCycling/config.yml` (`cooldown-seconds: 0`, `consume-emerald: false`) y recargar con `sudo docker compose exec minecraft rcon-cli easyvtc reload`.
2. **Asignar Permisos en LuckPerms:** Otorgar permisos al grupo default (`essentials.sethome`, `essentials.home`, `essentials.tpa`, `essentials.tpaccept`, `essentials.spawn`).
3. **Registrar Usuarios en Whitelist:** Agregar a los jugadores con `sudo docker compose exec minecraft rcon-cli whitelist add <Nick>`.
